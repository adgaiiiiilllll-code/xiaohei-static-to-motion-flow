# 小黑配图静态转动态流程

把小黑动态视频做成一条可审图、可生成、可交付的流程。优先解决“这句话该不该做小黑分镜、怎么动、如何交给视频平台”，而不是把所有口播都动画化。

## 先判断任务

- 已有口播或脚本：先把每一段标成 **小黑分镜 / 录屏 / 真人口播 / 已完成素材**。只有抽象流程、结果转化、章节转场和情绪记忆点优先做小黑分镜。
- 要做连贯故事或商业转场：走 **故事视频** 路线。
- 要让一张插画活起来：走 **单张图微动效** 路线。
- 用户只要文字方案、标题或提示词：不要擅自生成图片或视频。
- 用户已经完成开头、转场或某一段：保留该素材，不重复设计。

## 原小黑配图 Skill 的协同使用与署名

本流程以 Ian 的 `Ian Xiaohei Illustrations` 为静态配图前置能力，并在其基础上新增“静帧规划 → 图生视频 → 分镜交付”的工作流。

- 需要从口播或文章生成小黑静态配图时，优先让用户先安装并调用 `$ian-xiaohei-illustrations`；随后由本 Skill 继续处理首尾帧、动态方案和视频平台提示词。
- 发布、改编或再分发本 Skill 时，保留对 Ian 与原仓库的明确署名：<https://github.com/helloianneo/ian-xiaohei-illustrations>。
- 原 Skill 采用 MIT License；本 Skill 的原创增量可以独立使用，但不能删去原项目的版权和许可声明。具体署名文本见 [来源与许可](references/ian-xiaohei-attribution.md)。

## 共同视觉基线

除非用户明确修改，保持：

- 纯白背景、黑色手绘线条，橙色为主要动态/胶片强调，蓝色只做少量路径或提示。
- 小黑是纯黑豆形、两只白色圆眼、细线四肢；**没有嘴、鼻子或其他面部线条**。
- 一张图只讲一个核心动作。要做 4 秒以上动画时，预留一个主动作和 2–3 个可重复的辅助动作，避免把静帧塞得过满。
- 精确中文标题不要交给生图模型。预留标题区，确定后再独立排版。

## 故事视频路线

1. 从用户的初步主题提炼一个清楚的“输入 → 运转 → 输出”故事，不要求用户先写完每一镜。
2. 让 Agent 先产出时间线大纲；先生成前几张关键帧定风格，确认后再补全时间线。
3. 把全部时间线做成一张总览大板：总览为 16:9 时，每一个分镜格也必须是清晰的 16:9，不用模糊缩略图代替。
4. 每一张关键帧单独生成并验图后，再按时序写图生视频提示词。商业转场需要清晰升级：触发 → 加速运转 → 输出成片。
5. 用户需要交付时，将图片按时序整理；每张图片旁边放对应平台提示词。

## 单张图微动效路线

1. 出图前明确：该图将作为视频首帧或尾帧，要保留延展空间和稳定边界。
2. 选一个局部微动，不改变主体结构，例如纸飞机沿既有路径、小黑轻微呼吸、叶片摆动、胶片前行。
3. 动效提示词要锁定核心特征和既有物体，要求动作克制、可循环或能回到近似首帧。

## 图生视频提示词

先写“发生什么”，再写边界。不要把模型限制到没有动作，也不要只写“炫酷”。

- **常规教程插段 / 微动效**：默认 4–6 秒；若用户未另行要求，固定机位、无新增物体、无变形、无文字、无闪烁。明确哪些现有元素能动、哪些边框/卡片/设备必须稳定。
- **商业转场 / 连贯故事**：默认 8–10 秒；允许大胆镜头和调度，但必须锁定角色、关键物体、文字区与视觉语言。先征询是否要固定机位或循环。
- 当前用户主要使用即梦；默认给中文即梦提示词。用户要求时，再给 Omni 版本。不同平台版本应表达同一动作，不要让同一素材出现互相冲突的机位和物体限制。

## HTML 交付页

当用户要多张分镜的可执行交付，或明确要求整理时：

1. 在项目内创建一个素材目录；图片存到 images/，不覆盖原始文件。
2. 生成本地可打开的 HTML：按口播时间顺序排列，每张卡片左图右提示词，标出章节/用途，并给每个提示词复制按钮。
3. HTML 内的提示词使用用户当前语言；若用户要求固定机位或不得新增物体，必须逐条写入可复制提示词，而不是只放在页面说明里。
